## 保留跟踪，尚未实施

- [ ] **日志查询成本与保留策略**  
  `RequestLogRepository.query()` 每次分页都重新执行多个同步聚合；请求和连接日志目前没有清理策略。
  隔离合成数据库测量：单页 50 条，覆盖全部时间范围，1 次预热后 5 次采样；
  1 万条中位数 9.3 ms，10 万条中位数 99.0 ms、最大 107.4 ms。
  全部为成功 HTTP 请求，无真实用户数据；这证明查询成本随数据量增长，不代表生产环境延迟。
  下一步应测实际常用时间范围与筛选条件，独立设计列表/统计分离和缓存。
  日志保留涉及历史可见性，需明确期限、导出和运行中记录保护，再实施清理。
- [ ] **登录会话保留上限**  
  完成的会话仍在内存 Map 中保留到服务关闭。需要定义轮询结果的可查询期限，再增加终态会话 TTL；
  不应通过无条件删除刚完成的会话破坏客户端轮询。
- [ ] **历史迁移测试恢复**  
  `server/test/core.test.ts` 仍有 4 个跳过用例。
  原用例引用已删除的 `requestLog.log()`、旧列以及旧返回字段，不能简单取消 skip。
  下一步以真实旧版 SQLite 表结构构建夹具，验证身份模式、时间单位、取消归因和成功归因迁移。
- [ ] **HTTP 代理可读性整理**  
  `server/src/proxy/http-proxy.ts` 的多条语句挤在单行。
  单独做格式整理，再评估小函数提取；该项不是本次确认的行为缺陷，避免与生命周期修复混合。
