# Frontend Guidelines

## Stack and sources

- The admin UI lives in `web/` and uses React, TypeScript, Vite, Tailwind CSS, and real shadcn/ui primitives generated by the shadcn CLI into `web/src/components/ui/`.
- Product behavior and required pages come from `codex-router-mvp-design.md`.
- Motion-bearing composites live in `web/src/components/animate-ui/`. They are vendored the same way shadcn primitives are and are not edited for product styling.
- Fonts are assigned by script and by role: Inter owns Latin page text and falls through to Noto Sans SC for CJK (`--font-sans`), Roboto Mono is reserved for technical data (`--font-mono`), and Google Sans is loaded Latin-only for the product wordmark alone (`--font-logo`).

## Styling contract

- Use Tailwind utility classes for layout and component styling.
- Keep `web/src/index.css` limited to the Tailwind import, the font faces, CSS variables, base element rules, and the few named treatments (`route-flow-item`, `subtle-scrollbar`).
- Do not add CSS Modules or CSS-in-JS.
- The visual direction is a compact local console assembled from outlined cards over flat fills, with exactly one dark emphasis block per page and brand blue reserved for selection, routing and measurement.

## Reference implementations

The account routing page and the usage analytics page define the house style. New
pages and reworked pages copy their surface system rather than inventing one.

- `web/src/components/account/account-list.tsx` and `account-card.tsx` — the card grid, its route summary band, and its fixed-height scroll region.
- `web/src/pages/usage-page.tsx` — the twelve-column analytics grid, the `Panel` shell, and the emphasis hero.

When a rule below is ambiguous, these files settle it. When they contradict each
other, one of them is wrong; fix it rather than choosing freely.

## Surface system

- Every block is the same shell: a `--card` panel at `rounded-2xl` outlined with `ring-1 ring-foreground/10`, wrapping **one** inset of flat fill (`bg-muted`, `rounded-xl p-3`) that holds the content. Outline plus solid fill, never outline nested inside outline.
- Nesting stops at one level. A card holds one inset; an inset does not hold a second ring. A tile inside an inset returns to `bg-card` so the stack reads out, in, out.
- Use `ring-1 ring-foreground/10` for the panel outline, not `border`. `border-border` is for rules that divide content inside an inset.
- Radii step down inward: panel `rounded-2xl`, inset `rounded-xl`, icon tile `rounded-xl`/`rounded-lg`, chip `rounded-full`. Controls keep their shadcn radius (`rounded-md`) so they read as controls; the account search field is drawn as an inset of its toolbar and follows the inset radius instead.
- Exactly one emphasis block per page, and it carries the page's headline number: `bg-emphasis text-emphasis-foreground` outside, `bg-emphasis-surface` for its inset. A second one means the page no longer has a hero — the usage page test asserts there is only one.
- A panel header that pairs a title with a hint is a fixed band, not padding around text: a set height with `items-center`. `items-baseline` sits the smaller hint on the title's baseline, which puts it below centre — that is the mistake this rule exists to prevent.
- Every panel title carries a lucide icon at `size-4 text-muted-foreground` before the text, and an optional right-aligned hint at `text-xs text-muted-foreground/70`. On `Panel` the icon is a required prop, so a new card cannot ship without one.
- Page grids are `grid grid-cols-12 gap-4`; blocks claim spans (8/4 for a hero beside its breakdown, 6/6 for a pair of rankings, 12 for a reference strip). Card grids inside a panel use `gap-3`.
- A tint on a surface is only ever `--primary` at low alpha (`/8`, `/10`), and only to mark routing: the route summary band and the selected account's control. Nothing else tints a surface.

## Typography

- `--font-sans` for everything on a page. `--font-heading` is already wired into the shadcn title slots (Card, Dialog, Sheet, AlertDialog, Empty); apply it by hand only for section titles inside those surfaces, as `SECTION_TITLE` does in the account detail sheet. `--font-logo` is the wordmark only and must not appear in page content.
- Monospace is reserved for technical data: measured numbers, transport traces, raw payloads and identifiers presented as data. Names people read — model names, project paths, emails, an account ID used as a card heading — stay in the body face.
- Every number carries `tabular-nums`, so a value that updates in place does not shift its neighbours.
- `text-muted-foreground` is secondary content; `text-muted-foreground/70` is furniture (hints, captions, axis ticks, column labels). They are not interchangeable.
- Titles are `text-sm font-semibold` in a panel header and `text-2xl font-semibold tracking-tight` for the page `h1`.

## Tokens

- Colors are declared in three layers and code reaches only the outermost: raw values as `--palette-*`, semantic tokens (`background`, `card`, `muted`, `primary`, `warning`, `emphasis`, …) defined in terms of the palette, and components consuming semantic tokens alone. Never use a `--palette-*` value or a page-local hex in a component.
- Name a token for its role, not its appearance. `--emphasis` is the high-emphasis analytics surface; it happens to be dark blue today and must not be renamed or reasoned about as "the dark card".
- The emphasis surface goes _up_ in the dark theme, not down. At `0.16` it landed between `--background` and `--card` and read as a hole in the page; it must stay the most elevated block in both themes.
- Status must always include a text label; color is supplemental.
- Accent tone follows what a state asks of the reader, not what kind of state it is: `--muted-foreground` when there is nothing to do (including every healthy default), `--warning` when it clears on its own or is only a reminder, `--destructive` when routing is blocked until someone acts, `--primary` for the account traffic is routed through. A default state never wears an accent, or the exceptions have nothing to stand out against.
- `--warning` and `--destructive` are tuned to the same contrast weight (4.77:1 on the light card, ~6.2:1 on the dark one) so neither out-shouts the other. Re-check any change to these tokens against WCAG AA (4.5:1) in both themes.
- Chart series that measure the same quantity share one hue across five lightness steps (`--chart-1` … `--chart-5`). Step 1 is the least prominent against the theme's ground and step 5 the most, which means the dark ramp runs the opposite direction from the light one — otherwise the smallest series shouts the loudest. Do not give such series separate hues.
- Radii derive from `--radius`; do not introduce standalone radius values.

## Component seams

- shadcn primitives live in `web/src/components/ui/` and are owned by the shadcn CLI; do not edit them for product styling. Scope a deviation at the call site with an arbitrary variant (`[&_[data-slot=…]]:…`) instead — thinning the ScrollArea primitive once thinned every scrollbar in the app.
- Business composite components live in `web/src/components/` (for example `account/`, `gateway/`) and compose shadcn primitives.
- Pages live in `web/src/pages/` and compose existing components; they do not own reusable dialog, badge, button, or empty-state behavior.
- A page may define a local layout shell (`Panel`, `Ranking` in `usage-page.tsx`) when the shape is that page's own. Promote it to `web/src/components/` the moment a second page needs it.
- Shared API types and fetch behavior live in `web/src/lib/api.ts`; formatting helpers live in `web/src/lib/format.ts`; state predicates and thresholds live in `web/src/lib/account-state.ts`.

## Reuse gate

- Prefer an existing shadcn primitive before writing a generic UI component; write a business composite only when a role is product-specific (AccountCard, AccountUsage, AccountStatusBadge, ActiveAccountSelect, TransportTrace).
- Search `web/src/components/ui`, `web/src/components/animate-ui`, `web/src/components`, and direct imports before creating a component. Segmented switches already exist as animate-ui Tabs and are used by the accounts, usage, request-logs and preferences pages; do not hand-roll another set of toggle buttons.
- Import components directly from their files; do not add broad barrel exports.

## Page composition

- Keep Accounts and Settings as separate page components selected by the top-level app shell.
- Desktop layouts may use dense grids and side panels; below tablet width, switch to readable stacked cards without horizontal scrolling.
- A page either scrolls itself or fills the viewport and scrolls inside — never both. Pages whose main content scrolls internally (Accounts, Gateway, Request logs) opt into `lg:h-full` in the app shell; the usage page scrolls as a page and instead pins the height of the cards that could stretch.
- Cards sitting side by side that list a variable number of rows pin their body height and scroll inside it. A long list must not make one card taller than the card beside it.
- Where the scroll is incidental to a card, hide the scrollbar and fade the bottom edge (`bg-linear-to-t from-muted`) to say "there is more"; a bar as well is the same message twice. Where the scroll is the page's main region, show `subtle-scrollbar` and fade the edges as they come into play.
- The transport trace is the sole signature visual and must encode live Gateway-to-account flow, not serve as decoration.

## Accounts page rules

- The page is a comparison surface: exactly one account is live and the rest are standby reserves, and the layout must encode that asymmetry rather than render peer cards.
- Two panels stack the page: a fixed route summary band, and a list panel that takes the remaining height and scrolls internally.
- The route summary owns everything about the current route — the routed account, its auth status, its tightest remaining quota, and `清除路由`. None of that is repeated in a card, and `清除路由` never appears in one.
- The list is one shadcn RadioGroup rendering a card grid (`md:grid-cols-2 xl:grid-cols-3`), because exactly one of N accounts is live. Do not reintroduce a separate account picker or a per-row switch button.
- The radio _is_ the OpenAI mark in a rounded tile, taken straight from base-ui `Radio.Root` rather than the shadcn `RadioGroupItem` wrapper, because the control is the brand mark and not a dot. It is `aria-hidden` brand furniture styled as a control, and reuses `@/components/app/openai-mark`.
- The mark spins while an account is the route and from the moment it is asked to become one, so a switch reads as one continuous motion. A switch in flight must not change the cursor or the tile's colors — that flicker is what the spin replaces.
- An account that cannot be routed has a disabled control. Whether the control is locked follows routability, never the presence of a button.
- The list is filtered but never re-sorted: it keeps the server order, which is `created_at ASC`. Ranking by health or by remaining quota reshuffles cards as accounts are used, so a card is rarely where it was last seen. Anything that varies with usage or status must not decide card order.
- Filtering is a search field plus animate-ui Tabs carrying counts (全部 / 可路由 / 需处理 / 已停用).
- A disabled account's card dims as a whole (`opacity-65`); it does not restate "disabled" in every field.
- Card layout is fixed: a header outside the inset (control, account ID, 当前路由 chip, email, actions menu), then an inset carrying status and freshness on one line, the quota meters, and a footer rule with the billing line and at most one repair button.
- The account identity shown first is the real ChatGPT Account ID (`chatgptAccountId`), and it is a button that opens the detail sheet. It is a heading, so it is not monospaced.
- Never show a user-entered account label input; the add-account dialog starts official Codex Browser OAuth with no label.
- A repair button appears only where an account stays broken until someone acts (`relogin_required`, `error`). A deliberately disabled account is not a fault, and checking, waiting or rate-limited accounts clear on their own, so none of them get one; the actions menu still covers those cases.
- At most one qualifier per card. Plan, auth mode, credits, per-bucket windows and reset credits belong in the detail sheet.
- Detail sheet section headings are all `font-heading font-medium`; sections do not invent their own heading sizes or colors.
- Destructive actions (remove account) use shadcn AlertDialog instead of native `confirm()`.
- Icon-only actions get a shadcn Tooltip; account actions beyond the primary one live in a shadcn DropdownMenu.

### Quota meters

- Meters fill by remaining, not used, so a fuller bar always means a better route.
- Both windows are stacked in the card and always rendered from `SLOT_WINDOW_MINS` (7 天额度 / 5 小时额度), even when upstream omitted one, so cards keep the same height and the percentages stay aligned down the grid. Slots are filled by role, so a lone weekly window leaves the short slot empty rather than the other way round.
- One meter is three lines: name and remaining percentage, the bar, then the caption — a reset countdown, or the reason there is no number.
- The meter keeps the same shape in every state; only emphasis moves. Healthy meters use `--primary` on every card; the routed account is marked by its control and its chip, not by bar colour. `--warning` at or below `QUOTA_TIGHT_PERCENT` and `--destructive` at or below `QUOTA_CRITICAL_PERCENT` override it, and both thresholds live in `account-state.ts` rather than in the component.
- The track is `--foreground/15`, dark enough that a full bar still reads as a bar rather than dissolving into the inset.
- `null` usage renders as "未报告" with a muted rule, never as 0%.
- A window upstream omitted entirely reads as "无限制" with a full `--primary` rule and an `∞` where a percentage would sit, but only when the bucket itself was reported. When limits were never fetched, the slot keeps its name, says so, and draws a muted rule instead of claiming there is no cap. The empty-state rule is not a progressbar and must not be given that role.
- Reset times count down in two units ("3 天 5 小时后重置"), dropping the minor unit when it is zero.
- Subscription state is the date itself ("2026-09-15 到期"), not a word like "即将到期"; tone escalates but the date is always the label. A lapsed reminder is `--warning`, never `--destructive`, because it does not block routing.
- Staleness is carried by the freshness stamp — the one line already about how current the numbers are — and not repeated per meter.

## Usage page rules

- The page states its scope in the subtitle: local `CODEX_HOME` history, not per-account and not billing. Never present it as an account quota.
- The layout is one twelve-column grid: emphasis hero (8) beside the composition breakdown (4), two ranking cards (6/6), the heatmap (8) beside the workload panel (4), and the coverage strip (12).
- The hero is the page's one emphasis block: the headline total, three supporting figures, the trend chart on `--emphasis-surface`, and the legend. Everything else stays on light surfaces so the hero reads as the hero.
- Chart tooltips inside the emphasis block must set their own text color; `ChartTooltipContent` paints a light background but inherits the foreground, so it renders white-on-white otherwise.
- Recharts entrance animation is off (`isAnimationActive={false}`) — the growing-from-zero transition never completed here and left the bars invisible.
- Ranking cards pin their body height (`h-60`), hide the scrollbar and fade the bottom edge; a long list scrolls rather than stretching its neighbour.
- Every tooltip is a shadcn Tooltip. Native `title` attributes are not a fallback — they ignore the theme and cannot be reached by keyboard.
- A cell with nothing to report gets no tooltip.
- The heatmap describes the whole history, not the current filter, and says so in its hint. It reads unfiltered events server-side; a change to the filters must not move it.
- A figure quoted on its own spells the weekday out; only the axis, which has one glyph of room, uses the short form.
- The workload panel is six rows of `icon + label： value`, matching how the account cards list their facts. A two-column grid of six numbers leaves more air than it does work.
- Coverage is reference material, not a comparison. It reads as one short wide strip of all sixteen diagnostics in 2/3/4 columns with no scroll of its own, not as a tall column beside a wide chart.
- The range switcher is animate-ui Tabs, matching the accounts page. Ranges are `1d`/`7d`/`14d`/`30d`/`90d`/`all` and the set is shared with the server's `CodexUsageRange`.
- Model and project names are labels people read, so they are not monospaced; the measured numbers beside them are.

## Interaction and accessibility

- Every control uses a native semantic element, visible keyboard focus, an accessible name, and a disabled/busy state where applicable.
- Tailwind preflight leaves interactive elements on the default arrow, so `index.css` restores `cursor: pointer` for buttons, `role="button"`, `role="radio"` and `role="tab"`. A control that sets `aria-disabled` while busy drops out of that rule and must hold the cursor explicitly.
- Icons are lucide-react and `aria-hidden`: `size-4` in a panel header, `size-3.5` inline beside text, `size-[18px]` inside a `size-9` tile. An icon in a tile marks a subject; a bare icon marks a line.
- Anything truncated is reachable another way — a Tooltip on a focusable element, or the detail sheet.
- Dialogs trap focus, close with Escape, and restore focus to the trigger.
- Respect `prefers-reduced-motion`; no essential state may depend on animation. The routing spin and the transport flow are both gated on it.
- Empty and error states explain the next action in plain language and use shadcn `Empty`.

## Verification

- Layout claims are measured, not eyeballed: read back the rendered geometry (element rects, computed colors sampled from the canvas) before asserting that something is centred, aligned or contrast-safe. `oklch()` strings cannot be parsed as RGB.
- Check both themes. A token that works on the light card can read as a hole on the dark one.
- Lock a rule that took work to find into a test — the single emphasis block, the pinned ranking heights, the panel header band, the meter thresholds — so the next redesign has to argue with it rather than quietly undo it.

## Exceptions

- All faces are bundled locally through `@fontsource-variable` and a Latin-only `@font-face` for the wordmark; nothing is fetched from a font service at runtime. System fonts remain the fallback.
- Prompt logging remains visibly locked off and must not be exposed as an enabled control.
